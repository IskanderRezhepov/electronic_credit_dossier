# Электронное кредитное досье — версия 0.5

Программа читает цифровые PDF, сканы PDF, изображения, DOCX и TXT. Она классифицирует документы и извлекает ключевые поля.

## Поддерживаемые семейства документов

- договор купли-продажи;
- договор финансового лизинга / заявление о присоединении;
- акт приёма-передачи;
- график погашения;
- дополнительное соглашение;
- договор гарантии / поручительства;
- счёт / счёт-фактура;
- квитанция о подписании;
- неизвестный документ с универсальным извлечением ИИН/БИН, VIN, IBAN, DOC ID и денежных сумм.

## Важный принцип

«Прочитать любой файл» и «точно понять любой новый шаблон» — разные задачи. OCR читает текст почти любого скана, но смысловые поля нового шаблона требуют либо специального парсера, либо ручной проверки. Поэтому программа показывает источник, страницу, уверенность и статус каждого значения.

## Запуск

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python run.py
```

Открыть: http://127.0.0.1:5000

## Исправление v1.0.1

Исправлена ошибка:

```text
read_document() got an unexpected keyword argument 'ocr_cache_dir'
```

Причина: маршрут передавал параметр OCR-кэша, но публичная функция
`read_document()` ещё не принимала его в своей сигнатуре.


## Исправление v1.0.2

Исправлена ошибка:

```text
name 'hashlib' is not defined
```

В `document_reader.py` добавлены обязательные импорты `hashlib` и `json`.

Также улучшено определение ИИН/БИН по ролям:

## Исправление v1.0.3

Исправлена ошибка `first argument must be string or compiled pattern`.
Причина: регулярные выражения для ролей ИИН/БИН были одноэлементными
кортежами из-за завершающих запятых. Теперь это строки regex.

Также добавлена защитная проверка типа шаблона и расширено OCR-извлечение
суммы и даты в графиках платежей.

## Версия 1.5 — междокументная сверка

При одновременной загрузке нескольких связанных документов программа формирует сводку электронного досье и проверяет только подтверждённые поля:

- совпадение ИИН/БИН одной и той же роли между документами;
- совпадение связанных и основных номеров договоров;
- совпадение стоимости в ДФЛ, ДКП и актах;
- совпадение суммы финансирования и графика;
- комплектность базового пакета: ДФЛ, ДКП, акт, график.

Неоднозначные поля со статусом «Нужно подтвердить» не используются как факты при автоматической сверке. Результаты сверки сохраняются в JSON и на отдельном листе Excel «Сверка досье».

## Версия 1.6 — структурированные таблицы

Добавлено консервативное извлечение строк из графиков платежей и перечней имущества/VIN.
Таблицы показываются в интерфейсе, сохраняются в JSON и экспортируются на отдельные листы Excel.
Для OCR-таблиц программа не придумывает пустые ячейки: неоднозначные результаты помечаются как требующие сверки.

## Версия 1.7 — контроль качества и снижение ложных результатов

- повреждённый скрытый OCR-слой PDF больше не считается цифровым текстом
  качества 0.99; такие страницы повторно распознаются Tesseract;
- добавлен тип «Соглашение о прямом дебетовании банковского счёта»;
- упоминание договора гарантии внутри другого документа больше не меняет тип
  всего документа на «Договор гарантии»;
- строки вроде `npezurpuuaaarenen` больше не принимаются за VIN;
- графики внутри договоров субсидирования не публикуются как структурированная
  таблица без надёжной информации о координатах столбцов;
- двуязычные дубликаты строк графика объединяются по дате;
- небезопасные таблицы с неизвестной семантикой двух колонок не выводятся;
- добавлены роли «Залогодатель», «Отправитель» и «Получатель».


## Версия 1.8 — ручное подтверждение и исправление полей

На странице результата теперь можно:

- редактировать извлечённое значение;
- отметить поле как автоматически определённое, кандидат, подтверждённое,
  исправленное или отклонённое;
- сохранить исходное значение и исходный статус для аудита;
- повторно открыть сохранённый результат по адресу `/results/<result_id>`;
- автоматически пересчитать сводку досье после ручной проверки;
- автоматически пересоздать JSON и Excel после сохранения;
- исключить отклонённые поля из междокументной сверки.

Для списков и словарей значение редактируется как JSON. Для списков также
поддерживается построчный ввод, если оператор случайно удалил JSON-разметку.

# Электронное кредитное досье — версия 0.5

Программа читает цифровые PDF, сканы PDF, изображения, DOCX и TXT. Она классифицирует документы и извлекает ключевые поля.

## Поддерживаемые семейства документов

- договор купли-продажи;
- договор финансового лизинга / заявление о присоединении;
- акт приёма-передачи;
- график погашения;
- дополнительное соглашение;
- договор гарантии / поручительства;
- счёт / счёт-фактура;
- квитанция о подписании;
- неизвестный документ с универсальным извлечением ИИН/БИН, VIN, IBAN, DOC ID и денежных сумм.

## Важный принцип

«Прочитать любой файл» и «точно понять любой новый шаблон» — разные задачи. OCR читает текст почти любого скана, но смысловые поля нового шаблона требуют либо специального парсера, либо ручной проверки. Поэтому программа показывает источник, страницу, уверенность и статус каждого значения.

## Запуск

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python run.py
```

Открыть: http://127.0.0.1:5000

## Версия 1.5 — междокументная сверка

При одновременной загрузке нескольких связанных документов программа формирует сводку электронного досье и проверяет только подтверждённые поля:

- совпадение ИИН/БИН одной и той же роли между документами;
- совпадение связанных и основных номеров договоров;
- совпадение стоимости в ДФЛ, ДКП и актах;
- совпадение суммы финансирования и графика;
- комплектность базового пакета: ДФЛ, ДКП, акт, график.

Неоднозначные поля со статусом «Нужно подтвердить» не используются как факты при автоматической сверке. Результаты сверки сохраняются в JSON и на отдельном листе Excel «Сверка досье».

## Версия 1.8 — ручное подтверждение и исправление полей

- на странице результата отображается время чтения/OCR, извлечения и общее время;
- показывается число страниц, загруженных из OCR-кэша;
- для неопределённых ИИН/БИН и IBAN рассчитываются до трёх вероятных ролей;
- рядом с кандидатом показывается подсказка роли и процент;
- при выборе кандидата рекомендуемая категория автоматически подставляется
  в форму ручного добавления, но оператор всё равно подтверждает решение.


## Версия 2.3 — формальная проверка ИИН/БИН, IBAN и VIN

- ИИН/БИН проверяются по длине и контрольной сумме;
- казахстанские IBAN проверяются по длине, префиксу KZ и MOD-97;
- VIN проверяются по длине и допустимому набору символов;
- автоматически извлечённое значение, не прошедшее проверку, переводится
  в статус «Кандидат» и получает пониженную уверенность;
- подтверждённое вручную значение не удаляется, но рядом остаётся предупреждение;
- для типичных OCR-подмен O/0, I/1, S/5, B/8 и других символов программа
  предлагает до пяти исправленных вариантов, если они проходят проверку;
- исправление можно применить одной кнопкой, после чего поле автоматически
  помечается как «Исправлено»;
- невалидные автоматические ИИН/БИН, IBAN и VIN не используются в сводке
  досье как подтверждённые факты;
- результат проверки экспортируется в Excel.


## Версия 2.4 — координатное чтение таблиц

- для цифровых PDF сохраняются координаты каждого слова из PyMuPDF;
- для OCR-страниц сохраняются координаты слов из первого прохода Tesseract;
- графики платежей сначала восстанавливаются по координатам заголовков и колонок;
- спецификации техники сначала восстанавливаются по координатам колонок;
- извлекаются отдельные колонки даты, основного долга, вознаграждения, платежа и остатка;
- для техники разделяются наименование, модель, количество, VIN, цена единицы и общая сумма;
- если координатное чтение не даёт надёжного результата, используется прежний текстовый алгоритм;
- интерфейс показывает количество слов с координатами и отметку «Координатное чтение»;
- пустые и неоднозначные ячейки не заполняются догадками.


## Версия 2.5 — просмотр исходного документа и подсветка источника

- загруженные PDF и изображения сохраняются вместе с результатом анализа;
- рядом с полем, у которого определена страница, появилась кнопка «Показать»;
- документ открывается в модальном просмотрщике на нужной странице;
- значение подсвечивается по координатам цифрового текста или OCR;
- доступны переходы на предыдущую/следующую страницу и ввод номера страницы;
- оригинал можно открыть в отдельной вкладке;
- для старых результатов предпросмотр недоступен, поскольку исходные файлы в
  предыдущих версиях не сохранялись;

## Версия 2.6 — редактирование структурированных таблиц

- строки техники и графика платежей редактируются по отдельным колонкам;
- можно добавить новую строку или удалить ошибочно распознанную;
- для всей таблицы задаётся статус: извлечено, требует проверки,
  подтверждено или исправлено;
- исходная строка сохраняется в `original_row`, удалённые строки — в
  `deleted_rows`, поэтому изменения можно аудировать;
- после сохранения автоматически пересчитываются количество техники,
  уникальные VIN, суммы по графику и другие сводные показатели;
- выполняются базовые арифметические проверки:
  `количество × цена единицы = общая стоимость` и
  `платёж = основной долг + вознаграждение`;
- исправленные таблицы попадают в обновлённые JSON, Excel, карточку клиента и
  междокументную сверку.

## Версия 2.7 — арифметическая и междокументная сверка сумм

- проверяется `количество × цена единицы = сумма позиции`;
- сумма строк спецификации сравнивается с суммой договора, акта и стоимостью предмета лизинга;
- стоимость техники сравнивается между договором купли-продажи, договором лизинга и актом;
- в графике проверяется сумма основного долга, вознаграждения и платежей;
- проверяется цепочка остатка: предыдущий остаток минус основной долг должен давать новый остаток;
- сумма основного долга графика сравнивается с суммой займа или финансирования;
- критические денежные расхождения выделяются отдельно;
- в сводке и Excel показываются количество арифметических проверок, число расхождений и максимальная разница.


## Версия 2.8 — просмотр кандидатов и неопределённых страниц

- для каждого кандидата программа ищет его фактическое положение на странице;

- возле кандидата появилась кнопка «Показать · стр. N»;

- кандидата по-прежнему можно нажатием перенести в форму ручного добавления;
- если место кандидата в документе не найдено, это явно отображается;
- добавлен блок «Неопределённые или плохо прочитанные страницы»;

  или отсутствующими координатами;

  первые страницы;

## Версия 2.9 — повторный OCR одной страницы
